# Asset library (design)

Status: accepted, not implemented. Decision record: [README → D22](README.md#d22-asset-library).
Prefabs are deferred. Baking is a separate, deferred topic: [Visual assets](VisualAssets.md).

## Goal

Graphics are code (D1), so a project has nothing like Unity's Project window to browse. The library gives ready-made
graphics and audio a place on disk and a browser in the editor. It is for finding, previewing and reusing assets.
It places nothing on screen and adds no components: there is no dragging into a scene (Design goal 2).

Using it is optional. A project may keep its drawings anywhere; only what is under the asset folders is shown.

## Folders

| Folder | Contents | Editor |
| --- | --- | --- |
| `Engine/Assets/Graphics` | Ready-to-use graphics shipped with the engine | Read-only |
| `Game/Assets/Graphics` | The project's graphics | Free foldering |
| `Game/Assets/Audio`, `Game/Assets/Fonts` | Runtime files, as today | Browse and preview; no moving in v1 |

`Graphics` and `Prefabs` are reserved names under `Game/Assets`. They hold source code, so they are excluded from
every copy of the asset folder: `engine_add_game`, the editor worker, and the `release` package.

## Set assets

There is one graphic model: **every graphic is a set**. A single drawing is a set of one. Most engine defaults are
real sets (for example all icons, drawn by one function from an enum).

```cpp
// Icons.asset.cpp: compiled into the editor worker only
const GraphicAsset Icons{
    .items = IconItems, // id, display name, tags
    .draw = [](Painter& paint, const FloatRect& box, int item, float time) { /* draw item fitted to box */ },
    .usage = "DrawIcon(paint, Icon::{item}, center, size, style);",
};
```

- A set of one appears as a plain tile. A larger set shows a count badge and opens like a folder.
- Search looks inside sets, so "Star" finds `Icons › Star`.
- "Copy usage" fills `usage` with the item's name.
- Drawing into a box means thumbnails and the viewport share the same code.
- C++20 cannot list enum names, so the item table is written by hand, like other enum-ordered tables.

The API above is a sketch.

## Catalog and Release

Registration lives in `X.asset.cpp`, collected by a recursive glob into the editor worker only, using the object
library method that already protects static registrars from the linker. Games call the drawing directly (`DrawGoblin`)
and never look assets up by string, so Release contains no catalog.

## Editor panel

A dockable Assets panel in the lower editor area, in the style of Unity's Project window, separate from the scene
catalog: folder tree on the left; breadcrumb, search, tile size and a tile grid on the right.

- **Shared viewport:** one click opens the graphic in the normal viewport, with the Inspector and Tuning panels. A
  back button returns to the previous scene, because the running scene's state is lost.
- **Tiles, not files:** `Goblin.h`, `Goblin.cpp`, `Goblin.asset.cpp` and `Goblin.tuning.json` are one tile, which can
  be expanded.
- **Two data sources:** the editor scans the disk for the tree; the worker supplies metadata and previews. The tree
  survives a broken build, and a new file appears as "not built yet".
- **Actions:** new folder, move, new graphic (a skeleton only, generated by a `python Engine` command; the rest is
  written in code), show in Explorer, open code, copy usage.
- **Agents:** `ctl find` results gain a kind, and an asset opens through `ctl` like a scene.

### Moving and renaming

Code refers to assets through literal `#include` paths. Moving an asset or folder in the panel updates the matching
`#include "Assets/Graphics/..."` lines across the project, generated tuning includes among them, and rewrites nothing
else. A move made outside the editor shows up as a clear compile error. Engine assets are read-only, so their paths
do not change.

Renaming is a code refactor (file, symbols, callers), so the panel does not offer it.

**Not modules:** C++20 modules would avoid the rewrite, and a small test on the project toolchain built correctly. They
were rejected because they only simplify this rare operation, while the asset's own tuning include stays path-based and
renames remain refactors. The cost is permanent: weaker IDE support around `import`, CMake 3.28, names unique across the
project, tooling that assumes `.h`, and a split rule for assets versus other code. Assets can migrate later if IDE support
matures.

### Thumbnails

Thumbnails are part of v1, since a grid is of little use without them. The worker's image channel carries only the
viewport today, so the plan is untested:

1. The worker draws visible tiles into a `Surface` and writes PNGs under `build/`.
2. The editor reads those files, so old thumbnails remain visible while a build is broken.

Thumbnails are still images; an asset may give a `thumbnailTime`. Animation is watched in the viewport. Playing on
hover is not in v1.

### Audio

- Clicking a sound does not touch the viewport or the running scene. The Inspector shows a small player: play/stop,
  loop, volume, duration.
- The editor process is the preferred player because it works during a broken build. Whether it can open an audio
  device is unchecked; the fallback is the worker's `AudioSystem`.
- Audio cannot move in v1: audio catalogs hold file paths as strings.
- The worker knows the catalog, so the panel can mark files the game does not use.

## v1 order

1. Exclude source folders from copying and packaging; registration; `ctl` support.
2. Panel: disk scan, tree, grid, search, audio player.
3. Thumbnails.
4. Engine default sets (first candidate: icons).
5. New-graphic skeleton and folder actions, with include updates on move.

## Deferred

**Prefabs.** A prefab would bind logic, view and tuning into one named, spawnable unit, with variants as a tuning base
plus diff files. It is too generic to fit everything yet. Earlier decisions for when it returns: no entity/component
system, no drag-and-drop composition, the editor generates skeletons only, and logic stays outside the asset folder
because headless test targets must not pull in drawing code.
